# 提交门禁：pre-commit 暂存源码 oxlint 强制、pre-push typecheck+test 守门

## 背景

仓库没有 CI：代码进入 `main` 之前的自动质量关只剩 git 事件本身。AGENTS.md 已约定英文 conventional commit，但没有任何机器强制；`pnpm lint` 只靠人记得跑。

- oxlint（ADR-0002）没有内置 `--staged`/`--changed` 能力，且默认规则只开 `correctness` 类目、默认对纯警告 `exit 0`（空跑不报错）。
- simple-git-hooks@2.14 自带 `postinstall` 脚本，pnpm 11 的 `allowBuilds` 需要放行，否则钩子装不上（仓库已知 gotcha，见 PROJECT.md）。
- 兄弟仓库 `WebSocket学习` 已确立 house style：simple-git-hooks + lint-staged，pre-commit 对**暂存文件**跑 lint `--fix` 并自动重新暂存。

## 决策

- **pre-commit = lint-staged → `oxlint --fix --deny-warnings`**，glob `*.{ts,tsx,mjs,cjs,js}`：只检查**本次暂存**的源码，避免被无关的未提交改动连坐；`--fix` 自动修复并重新暂存；`--deny-warnings` 让门禁对警告也亮红灯，不留静默放行的口子。oxlint 不 lint `.json`，例行规格提交（只动 json + 产物）钩子空跑、零摩擦。
- **pre-push = `pnpm typecheck && pnpm test`**：推送是进入 main 前的最后自动关，typecheck（~7.6s）+ test（~6.9s）作为无 CI 的补偿，约 15s/次可接受。
- **规则面保持 oxlint 默认**（`correctness` 类目）：本轮只搭门禁**机制**，不动规则面；规则增强（如启用 suspicious/pedantic）是独立决策，另行 ADR。
- **不引入 commitlint**：commit message 规范继续靠 AGENTS 约定 + PR review，不增加依赖面。
- **配置放 package.json**：`simple-git-hooks` 与 `lint-staged` 两个键；`prepare: simple-git-hooks` 保证 install 后自动重装钩子（与兄弟仓库一致）；pre-commit 命令用 `pnpm exec lint-staged` 而非兄弟仓库的 `npx lint-staged`——本仓库 `devEngines.packageManager: pnpm` 会让 npx 拉起的 npm 报 EBADDEVENGINES 硬错（冒烟实测），`pnpm exec` 绕开 npm 层；`pnpm-workspace.yaml` 的 `allowBuilds` 放行 `simple-git-hooks` 的 postinstall（同时 `engines.node` 提升到 `>=22.22.1`，对齐 lint-staged 的运行时要求）。

## 后果

- 全绿成本：commit 增量近乎为零（lint-staged 只跑暂存文件），push 每次约 15s。
- 提交被拦 = 暂存源码存在 oxlint 错误或未修复的警告；`--fix` 已尽力自动修复，剩下的人工修掉重试即可。约定不使用 `--no-verify` 绕过。
- 门禁强度上限 = oxlint 默认规则面（`correctness`）；要更严格需后续 ADR 显式声明 `.oxlintrc`。
