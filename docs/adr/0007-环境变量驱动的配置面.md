# 环境变量驱动的配置面(config.ts)

## 背景

路径常量硬编码在源码里且全部相对 cwd:`src/clip/run.ts` 的 `EXPORTS_DIR = 'media/exports'`、`src/snap/run.ts` 的 `SCREENSHOTS_DIR`/`TEMP_DIR`;工具二进制已有环境变量(`src/common/ffmpeg.ts` 的 `FFMPEG_BIN`/`FFPROBE_BIN`)。要求把硬编码改为环境变量管理,必要时引入 dotenv。事实约束:规格 JSON(版本化)里的 `source` 是 `media/raw/videos/...` 相对路径;Node 为本机 v24(**≥20.6 原生支持 `process.loadEnvFile`**);仓库无 dotenv、无 `.env`,`.gitignore` 未忽略 `.env`。

## 决策

- **配置面只有五个旋钮**:`RE1999_EXPORTS_DIR`(clip 规格扫描基准)、`RE1999_SCREENSHOTS_DIR`(snap 规格扫描基准)、`RE1999_TEMP_DIR`(snap 探针临时目录),加 `FFMPEG_BIN`/`FFPROBE_BIN`(保留通用名、不加前缀)。**领域常量不是配置**——帧率 25、纠偏窗口上限 64、纯色帧判定阈值、`epNN` 命名、ASCII 路径规则保持常量。
- **`source` 路径不是配置**:规格 JSON 的 `source` 字段是数据(版本化、cwd 相对),不是旋钮;`media/raw` 只读规则不变。不引入"整体搬 media 根"的旋钮——那会静默破坏全部版本化规格。
- **原生机制,不引入 dotenv**:`src/common/config.ts` 用 `existsSync` 守卫 + `process.loadEnvFile()` 一次性加载(可传路径便于测试);`loadEnv()` 在 `src/main.ts` 最先执行;配置值通过**惰性 getter** 读取,测试可用 `vi.stubEnv` 注入,不读真实环境。
- **优先级**:CLI 显式参数(commander `-m`/`-o`/`--ep`/`--crf`/`--preset`) > 环境变量(shell 优先于 `.env` — Node `loadEnvFile` 不覆盖已存在变量,含空串)> 代码默认。
- **校验**:空值/纯空白直接报错;含非 ASCII 字符的值报错(路径 ASCII 规则)。
- **`.env` 入 `.gitignore`,`.env.example` 进 git** 作为文档化默认。

## 后果

- 不设任何环境变量时行为与改造前完全一致(默认值即旧常量),向后兼容。
- cwd 相对假设仍是默认,但显式可覆盖;环境变量值可以是绝对路径(`join`/`resolve` 语义兼容)。
- 测试镜像 `tests/common/config.test.ts`(每模块一测试文件),其余测试不触碰真实环境。
- 未来若真要整体搬迁 `media/` 根(换素材盘等),需先改写版本化规格数据,不在配置面内解决。
