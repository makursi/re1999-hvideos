# 单一入口：re1999 多命令程序（main.ts）

## 背景

src 目录重组（按流水线分目录）时要求"单一入口文件"。但项目刻意有双 CLI（ADR-0004 领域解耦）：`pnpm clip` 与 `pnpm snap`。字面"单一入口"有三种读法：合并成一个 CLI 程序 / 保留双入口但做薄 / 库式 index.ts。合并 argv 层不违背领域解耦——clip 与 snap 共享的只有机制（run-common/discovery/time/ffmpeg），领域模型（manifest vs frames.json、in/out vs at、mp4 vs 图片）从不跨流水线。

## 决策

- **单一入口 `src/main.ts`**：一个 commander 程序 `re1999`，`clip` / `snap` 为子命令（各自保留 run/list 子命令）。`src/clip/run.ts` / `src/snap/run.ts` 分别导出 `buildClipCommand` / `buildSnapCommand`，main.ts 只做接线（.addCommand）。
- **`pnpm clip` / `pnpm snap` 保留为转发别名**（`tsx src/main.ts clip` 等）：日常操作零影响；需要完整程序时用 `pnpm re1999`。
- **源码按流水线分目录**：`src/clip/`（manifest + run）、`src/snap/`（framespec + solid + shift + run）、`src/common/`（run-common + time + discovery + ffmpeg）。solid/shift 名义上是通用概念（CONTEXT.md 有词条）但实际只有 snap 消费，跟随消费者；ffmpeg 两端混合暂不拆（probeDuration/runFfmpeg 共用，是独立的拆分话题）。
- **纯组织重构**：CLI 语义、导出行为、日志文本均不变；测试镜像为 `tests/clip|snap|common/`。

## 后果

- 子命令的 `--version` 保留在各命令上（原样），主程序另加 `re1999 --version`。
- 若未来把两个流水线拆成独立发行物，只需把 build*Command 各起一个入口即可，拆回成本低。
- 路径引用同步更新（AGENTS.md source map、re1999-snap 技能内 `src/snap/solid.ts`、CHANGELOG 追加条目不改历史）。
