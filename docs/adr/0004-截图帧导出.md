# 截图帧导出：独立脚本 + 帧级精确 + 按条目格式

## 背景

需要从视频提取特定帧存为图片（jpg/png/webp，即"截图"）。选项：扩展现有 `clip` 管线 vs 独立脚本。既有事实（ADR-0001 实测）：素材关键帧间隔 4~7 秒，流拷贝/快速 seek 的吸附误差可达 ±7 秒——对"截出我要的这一刻"是致命伤，截图必须帧级精确。

## 决策

- **独立脚本 `pnpm snap`**，与 clip 管线解耦：spec 结构（时间点 `at` 而非范围 `in/out`）、产物（图片而非视频）、取帧语义均不同，塞进同一管线会污染"片段"领域模型。
- **来源 = 原始素材**（`media/raw/.../epNN.mp4`），`at` 为**绝对时间戳**（复用 `parseTimeToSeconds`，支持秒数 / `MM:SS` / `HH:MM:SS[.mmm]`）。不依赖导出产物存留，母版未压缩质量最好，与 ADR-0001"从原片精确取"一致。
- **帧级精确**：`-ss <at>` 放 `-i` **之后**（输出 seek，从目标前最近关键帧精确解码）。单张截图解码成本仅关键帧间隔内的百余帧，毫秒级。
- 每条截图一个 `format`（jpg/png/webp），产物 = `media/screenshots/{dir}/{id}.{format}`；`dir` 缺省跟随 spec 所在目录。
- 质量默认：png 无损无参数；jpg `-q:v 2`；webp `-quality 90`。先写死，不参数化，够用再提。

## 后果

- 截图不依赖导出产物，可随时复现（原片 + frames.json 均在即可）。
- 单张截图的帧级精确编解码开销可忽略；如未来需要"关键帧最近吸附"的快速预览再提供 flag，不改默认语义。
- webp 单帧输出依赖 ffmpeg 版本对 `-frames:v 1` + webp muxer 的支持；若遇旧版本写出多帧动画，再补 `-loop 0`/`-update 1`，属已知兼容点。
