# 每集清单跟随产物目录，CLI 按集扫描

## 背景

原本以根级 `manifest.json`（全部集的 clips）为 CLI 唯一输入，产物统一落到 `media/exports/{id}.mp4`。新需求加入"截图帧导出"能力，并要求**剪辑与截图分目录管理**、**规格文件跟随产物行目录**。单根 manifest 无法表达"一集一撮产物 + 一撮规格"，也无法与截图规格（每集一份 `frames.json`）对称。

## 决策

- 剪辑清单按集拆分：`media/exports/epN/manifest.json`，跟随该集剪辑产物目录。
- 截图规格按集拆分：`media/screenshots/epN/frames.json`，跟随该集截图产物目录。
- `pnpm clip run` 无参扫描 `media/exports/*/manifest.json` 逐集执行；`--ep epN` 只跑一集；`-m <path>` 保留显式单文件模式。
- `pnpm snap` 同构扫描 `media/screenshots/*/frames.json`。
- 规格条目可显式指定产物目录（`dir`），缺省 = 规格文件自身所在目录（目录映射显式优先）。
- `.gitignore` 忽略媒体产物目录，但用 negate 规则**保留规格文件进版本库**（规格是输入，产物是生成物）。

## 后果

- 单集产物目录自包含："这一集的配方（manifest/frames.json）+ 产物"放一起，按集管理、按集重跑。
- 规格文件因 gitignore 例外而可版本化，与"media/exports 不提交"不冲突。
- 任何以根 manifest 为假设的既有工具（verify 脚本、技能文档）同步改为按集扫描。
- 后续多片段拼接（合辑）如跨集，再引入合辑级清单，不改变"片段"语义。
